<objective>
Build the text on-ramp estimators that make the segment→encode chain Pipeline-legal. Three things: (1) create the new `TextSegmenter` estimator wrapping the existing `segment()` function, whose `transform(text)` returns `List[str]` and whose `chunks_` fitted attribute preserves the `List[Chunk]` span info (D-01, TEXT-02); (2) turn `Encoder` into a `BaseEstimator`/`TransformerMixin` with thin `fit`/`transform` wrappers around its existing `.encode()`, and fix the QA-02 `_MODEL_CACHE` bug (key by `(model_name, device)`, stop the in-place `.to()` mutation); (3) apply the same thin `fit`/`transform` wrapper to `MorphologicalEncoder`.

Purpose: TEXT-02 requires `TextSegmenter` plus Pipeline-legal `Encoder`/`MorphologicalEncoder` emitting the `(n_chunks, n_features)` array the core consumes. These are the first two steps of the Pipeline composition test (Plan 07) and the convenience wrappers (Plan 05).
Output: `infodynamics/text/segmentation.py`, `embedding.py`, `morphology.py` with Pipeline-legal, lazily-loading text estimators.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → TextSegmenter | Raw text string in; pure in-memory regex/syntok segmentation, no I/O |
| Encoder/MorphologicalEncoder → HuggingFace Hub / local UDPipe model | Model identified by `model_name`/`model_path`; loaded (and on first run downloaded) from an external/local source |
| Encoder instances ↔ shared `_MODEL_CACHE` | Multiple estimator instances share a process-level model cache |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-03 | Tampering | Encoder._MODEL_CACHE in-place `.to(device)` mutation | medium | mitigate | This phase's QA-02 fix keys the cache by `(model_name, device)` and removes the in-place `.to()` mutation, so one instance can no longer silently move another instance's shared model to a different device (a real state-integrity/tampering bug) |
| T-03-04 | Elevation of Privilege | SentenceTransformer/UDPipe model load from `model_name`/`model_path` | high | accept | Loading a HuggingFace/UDPipe model can execute model-repo code; this is a pre-existing boundary NOT changed by this phase (the lazy-load call sites are preserved verbatim). `model_name`/`model_path` are trusted developer-supplied inputs in a library context. No new load surface is introduced; per `security_block_on: high` this is documented and accepted (unchanged surface), not a new high finding to block on |
| T-03-05 | Information Disclosure | first-run model download over network | low | accept | Download path unchanged from prior phases; occurs only on explicit estimator use with a developer-supplied model id |

Conclusion: the QA-02 cache fix *reduces* an existing Tampering risk. Model-load RCE (T-03-04) is a pre-existing, unchanged boundary with trusted input — no NEW high-severity threat is introduced by this phase's changes.
</threat_model>
